Purpose and scope

This guide explains how a WhatsApp customer journey becomes a managed GloAro lead, and how an administrator configures, monitors and intervenes in that journey. It covers the currently implemented GloAro Mart and GloAro Digital Network flows, the Admin panel, WhatsApp channels, integrations and operational safeguards.

1.1 Dashboard — daily control centre

The Dashboard automatically refreshes and shows Total, New, Follow-up, Closed and Today’s Leads; Customers; Active Conversations; a 14-day lead trend; and recent leads. It also raises attention banners when Google Sheet syncs are pending or admin notifications have failed.

Daily action: Check the warning banner first. Then open new leads, assign ownership where applicable, and review active conversations requiring a human response.

1.3 Customers and conversation history

Customers are identified by WhatsApp number within the workspace. The Customers list supports search; each profile shows captured customer data, full conversation history and linked leads. This gives the team context before contacting a person again.

1.5 Bot Menu — no-code content management

The Bot Menu page lists the active flow nodes. An administrator can edit message body, image URL, link URL, a menu’s button label, and its options. Changes apply on the customer’s next message without redeployment. New MENU or MESSAGE nodes can be created, then linked by setting an existing menu option’s target key. A node cannot be deleted while another node points to it; the Welcome node cannot be deleted.

Node typeRuntime behaviour
MENUDisplays tappable WhatsApp list options where supported; otherwise displays numbered text and waits for a valid selection.
QUESTIONPrompts for one answer, validates it and stores it in the active session.
MESSAGESends information and immediately continues to its configured next node.
ACTIONCompletes an operation such as CREATE_LEAD, TRACK_ORDER or END.

1.6 Simulator

The Simulator sends test messages through the same bot engine used by WhatsApp. It is the recommended way to validate new copy, menus, validation and lead creation before activating a live channel. Completed simulated flows create real database leads, so use a clearly recognisable test number and clean up or mark test data appropriately.

1.7 WhatsApp channel administration

Administrators can add one or more WhatsApp provider accounts. Supported adapters include Meta Cloud API, 360dialog, Gupshup, AiSensy and UltraMsg. Each account stores a label, number and provider-specific credentials; secrets are encrypted server-side and masked in the interface.

  • Test connection verifies the credentials with the selected provider.
  • Connect / Disconnect enables or disables bot delivery for that channel.
  • Default chooses the account used for outgoing messages.
  • Webhook displays the provider-specific URL and supports secret rotation.
Until a WhatsApp channel is connected, the bot runs in dry-run mode. Responses are logged for the Simulator / outbox rather than delivered to a customer.

1.8 Settings

Settings maintain company details, support phone/email/website placeholders, bot session timeout, admin notification recipient(s), and Google Sheets configuration. The Sheet connection can be tested before operational use. Settings are tenant-scoped, so each workspace has independent copy and integrations.

2.2 GloAro Mart

Mart menu: B2B Marketplace, B2C Marketplace, Become a Seller, Track My Order, Contact Sales Team.

B2B Marketplace

Choose category — Food & FMCG, Electronics, Fashion & Garments, Industrial Products or Other Products — then provide Company Name → Contact Person → Mobile Number → Product Requirement. The bot creates a GLOARO_MART / B2B_MARKETPLACE lead.

B2C Marketplace

Browse Products shares the configured website and returns to the B2C menu. Latest Offers shares the configured website and returns to the B2C menu. Customer Support captures Name → Mobile Number → Issue/requirement and creates GLOARO_MART / CUSTOMER_SUPPORT.

Become a Seller

Captures Business Name → Owner Name → Mobile Number → Product Category → Business Location (City). Product categories mirror the B2B categories. Creates GLOARO_MART / BECOME_SELLER.

Track My Order

Captures Order ID and calls the configured order lookup. If the lookup returns a match, the bot displays the live status and returns to Welcome. If no lookup is available or no order is found, it creates a support lead tagged GLOARO_MART / TRACK_ORDER and tells the customer the team will update them.

Contact Sales Team

Captures Name → Mobile Number → Requirement and creates GLOARO_MART / CONTACT_SALES.

2.4 Input validation

Questions specify the expected type: name, text, email, phone, city, PIN code, order ID or long-form requirement. The bot holds the customer on the current question until a valid answer is received; valid answers are retained in the session and later copied into the lead’s structured fields and raw-answer record.

3.2 Side effects after lead creation

  1. The lead is first saved to PostgreSQL; this is the system of record.
  2. A BullMQ job appends the lead to the configured Google Sheet.
  3. A separate BullMQ job sends the new-lead WhatsApp notification to the configured admin recipient(s).
  4. The bot sends the customer a confirmation and reference number.

The Sheet and notification jobs are asynchronous, so their availability never prevents a completed customer enquiry from being saved. Their status is shown on the lead and Dashboard.

3.3 Reliability and security controls

ControlHow it protects operations
Webhook idempotencyEach provider message ID is claimed before processing. A redelivered webhook is ignored rather than causing duplicate replies or duplicate leads.
Webhook signaturesMeta webhook signatures are checked against the preserved raw request body.
Queued retriesSheet and notification jobs retry with exponential backoff.
ReconciliationA periodic job re-queues leads whose Sheet sync never completed, including when Redis was unavailable at initial creation.
Tenant isolationCustomers, flows, settings, messages and leads are scoped to their tenant/workspace.
CredentialsProvider credentials are encrypted on the server and masked in API responses and the Admin UI.

4. Operating procedures

4.1 Recommended daily routine

  1. Open Dashboard and resolve any integration warning.
  2. Filter Leads by New; assign an owner and add a first-follow-up note.
  3. Check Active Conversations and take over any enquiry requiring a human answer.
  4. Move contacted leads to Follow-up; mark outcomes Closed.
  5. For failed delivery or Sheet entries, open the lead, validate settings, then use Retry sync.

4.2 Safely changing customer-facing content

  1. Use the Simulator to walk the affected branch from Welcome through completion.
  2. In Bot Menu, change message copy, menu label or options.
  3. For a new branch, create a node with an uppercase snake-case key, then set an existing option’s target to that key.
  4. Run the Simulator again; verify navigation, invalid-input handling and final lead category.
  5. Keep the Welcome node and referenced target nodes intact; deletion is intentionally blocked while references remain.

4.4 Quick troubleshooting

SymptomFirst checks
Bot does not reply liveWhatsApp channel is connected and active; correct webhook URL/secret is configured; provider connection test passes; conversation is not taken over.
Customer is stuckAsk them to reply 0 for Welcome. Review the session node and Bot Menu target links; test the branch in Simulator.
Duplicate webhook deliveryExpected redeliveries should be ignored by idempotency. Review webhook event logs only if no response was produced.
Lead missing from Sheet / no alertThe lead remains safely saved in the app. Inspect its sync badges/error, confirm settings, then click Retry sync.
Bot replies during agent workUse Take over first. Confirm the conversation is marked handed over before manual work continues.
Handover summary: The bot qualifies and records enquiries continuously; the Admin panel is the team’s operational workspace for prioritising, assigning, communicating and closing them. The database remains the authoritative lead record; Google Sheets and WhatsApp alerts are supported, retried operational copies.
